How the Lab Fits Together

Follow a contract from static analysis through a local attack, then compare it with the secured version.

  1. 01 / Source

    Scan the contract

    scanner_simple.py checks Solidity source for common issues; scanner.py can add Slither analysis.

  2. 02 / Local chain

    Deploy to Anvil

    The deployment script sends VulnerableBank.sol to Foundry's local test network.

  3. 03 / Test

    Run the exploits

    Python exploit scripts connect to the local contract and demonstrate its vulnerabilities.

  4. 04 / Compare

    Verify the fixes

    Deploy SecureBank.sol and compare its protections against the same attack scenarios.

All contract activity stays on the local Anvil network. No mainnet funds are used.

Vulnerabilities Covered

Reentrancy (SWC-107)

External call before state update leads to recursive withdrawal. Mitigated by using ReentrancyGuard and the checks-effects-interactions pattern.

Arithmetic Overflow (SWC-101)

Unsafe addition/subtraction in Solidity <0.8.0. Mitigated by using Solidity 0.8+ built-in checks or OpenZeppelin's SafeMath.

Access Control (SWC-105)

Public function transfers value without owner check. Mitigated by utilizing the onlyOwner modifier from OpenZeppelin.
